# 카페24 스마트디자인 적용 안내

이 결과물은 독립 실행되는 HTML 시안입니다. 실제 계정·스킨에 접근하지 않았으므로 바로 업로드하는 완성 스킨 패키지나 서버 연동 완료본은 아닙니다. 원래 스킨의 모듈과 주문 기능을 보존하며 아래 순서로 옮기세요.

## 1. 작업용 스킨 준비

관리자 디자인 관리에서 현재 디자인을 복사 또는 백업하고 복사본의 스마트디자인 편집창을 엽니다. 스킨마다 파일명과 메뉴 위치가 다를 수 있으므로 편집창에서 현재 레이아웃과 상품·게시판 화면을 먼저 확인합니다. 수정 중인 스킨은 대표 디자인으로 즉시 설정하지 않습니다.

## 2. 공통 파일 업로드

`cafe24-theme/assets/`를 스킨의 `/safety/assets/`로 업로드합니다. `style.css` 안의 이미지 경로는 assets 기준이므로 하위 폴더를 유지합니다. 기존 CSS 충돌이 있으면 `.safety-site` 부모 아래로 스타일 범위를 제한하고 원래 결제/회원 화면에 적용되지 않도록 확인합니다.

공통 레이아웃은 보통 `/layout/basic/layout.html`이며 메인은 별도 `/layout/basic/main.html`일 수도 있습니다. 실제 사용 중인 파일의 head에 다음 지시문을 추가합니다.

```html
<!--@css(/safety/assets/style.css)-->
<!--@js(/safety/assets/config.js)-->
<!--@js(/safety/assets/site.js)-->
```

원래 레이아웃의 `<!--@contents-->` 등 콘텐츠 삽입 지시문, 회원/장바구니 스크립트를 삭제하지 마세요. header/푸터 시안은 `partials/header.html`, `partials/footer.html`에서 가져와 기존 헤더/푸터 위치에 적용합니다. 포함 파일을 사용한다면 `/safety/partials/header.html` 등으로 업로드하고 `<!--@import(/safety/partials/header.html)-->` 형태로 불러옵니다. 스킨 편집창에서 import 동작을 먼저 미리보기로 확인하세요.

## 3. 각 페이지 적용 위치

| 시안 파일 | 적용할 화면 / 영역 | 작업 |
|---|---|---|
| index.html | 쇼핑몰 메인 `/index.html` | main 내부를 옮기고 기존 메인 레이아웃 지시문 유지 |
| products.html | 상품분류 `/product/list.html` | 인트로·분류 UI 적용, 반복 카드는 상품 모듈로 교체 |
| product-*.html | 상품상세 `/product/detail.html` | 스타일과 상세 레이아웃 참고, 기존 product_detail/옵션/구매 동작 유지 |
| solutions.html | 신규 `/safety/solutions.html` | main 내부와 공통 레이아웃 연결 |
| about.html | 회사소개 `/shopinfo/company.html` 또는 신규 페이지 | 소개·과정·방문 안내 적용 |
| cases.html, case-*.html | 선택한 설치사례 갤러리 게시판의 목록·읽기 | board_list/board_read에 카드와 본문 스타일 적용 |
| blog.html, post-*.html | 선택한 블로그 게시판의 목록·읽기 | 검색, 분류, 페이징, 관련 글을 실제 게시판 데이터로 연결 |
| contact.html | 비공개 문의 게시판 쓰기 화면 | 예시 form을 기존 board_write 폼으로 교체 |
| privacy.html | 실제 개인정보처리방침과 수집·이용 동의 화면 | 운영자 확정 문구로 교체 |

서브페이지에 전체 HTML 문서를 중첩해서 붙이지 마세요. `<main id="main">` 안의 본문만 옮기고 스킨의 레이아웃 지시문을 위에 유지합니다. ID `main`은 공통 레이아웃에 한 번만 사용하세요.

## 4. 경로를 실제 주소로 바꾸기

시안은 모든 HTML이 같은 폴더에 있다는 전제로 상대 경로를 사용합니다. 카페24에서 경로를 나누면 `assets/`를 `/safety/assets/`로 바꾸고 메뉴, 카드, 이전/다음, CTA 링크도 실제 절대 경로로 바꿔야 합니다.

- `products.html?category=...` → 실제 `/product/list.html?cate_no=관리자에서확인한번호`
- `product-*.html` → 실제 상품 모듈의 상세 URL 변수
- `blog.html`, `post-*.html` → 게시판 모듈이 제공하는 목록/읽기 링크 변수
- `contact.html` → 선택한 비공개 문의 게시판의 쓰기 주소
- 전화는 `tel:02-856-3853`, 스마트스토어는 기존 주소와 새 창 속성을 유지

번호는 `assets/config.js`에 `null`로 모아 두었습니다. 관리자에서 확인해 기록하는 용도이며, 해당 JavaScript 값이 카페24 서버 모듈의 속성을 자동으로 치환하지는 않습니다. `integration/product-list.html`의 `{{CATEGORY_NUMBER}}`도 실제 번호로 수동 교체해야 합니다. 임의의 게시판/분류 번호를 그대로 쓰지 마세요.

## 5. 실제 모듈 연결

상품 반복영역에는 `product_listnormal`을 사용하고, 상품명·이미지·상세 링크는 실제 상품 변수를 사용합니다. 메인 진열은 현재 스킨의 메인 진열 모듈과 진열 설정을 사용합니다. 상품 상세는 기존 `product_detail` 모듈 안의 옵션, 수량, 주문 버튼, 스크립트를 보존합니다. 시안에는 확인된 가격·재고가 없어 임의 금액이나 구매 완료를 표시하지 않습니다.

게시판은 실제 관리자에서 블로그/설치사례/후기/문의 용도를 정한 뒤 기존 게시판 화면을 복사해 스타일을 입힙니다. 기존 `board_list`, `board_read`, `board_search`, `board_paging`, `board_write`와 해당 스킨의 게시판 번호 접미사를 확인합니다. 글 6개는 예시 콘텐츠를 검토해 직접 등록합니다. 시안의 JavaScript 필터는 정적 목록에만 작동하므로, 서버 게시판을 연결하면 게시판의 실제 검색·분류·페이징으로 교체하세요. 인기 글은 조회수 집계가 연결되기 전에는 인기 순위로 표시하지 않습니다.

회원/로그인/장바구니 영역은 현재 스킨의 원래 모듈을 유지하거나 공통 내비게이션 옆에 배치하세요. 실제 상품 검색도 기본 스킨의 검색 폼을 유지합니다. 회원 데이터나 카페24 검색을 시안 JavaScript로 흉내 내지 않습니다.

## 6. 상담 전송 연결

`contact.html`의 `inquiry-form`은 입력 검증만 합니다. 전송 URL을 임의로 추측해 붙이지 마세요. 카페24에서 실제 비공개 상담용 게시판을 준비하고 원래 쓰기 폼의 action, 필수 보안필드, 등록 함수, 접근 권한을 그대로 사용합니다. 현재 예시 form과 site.js의 inquiry-form 처리 블록을 제거한 뒤 실제 필드에 디자인을 적용하세요.

업체명/연락처/설치 장소/제품/수량/멘트/문의내용을 본문 또는 지원 필드로 매핑합니다. 연락처가 공개 목록·검색 결과에 나타나지 않도록 비공개 설정을 검증합니다. 개인정보 목적·항목·보유기간·거부 안내를 실제 운영 방침과 맞추고, 전송 성공 문구는 서버가 저장 성공을 확인한 경우에만 표시합니다. 스팸 방지와 비회원 권한도 실계정에서 확인합니다.

## 7. 공개 전 마지막 확인

운영자 이름, 사업자등록번호, 주소, 통신판매업 신고 등 해당 쇼핑몰에 필요한 회사정보는 관리자에 등록된 실제 값으로 푸터에 연결합니다. `삼성물상`은 사용자 제공 철자를 그대로 사용했으므로 실제 납품처 명칭을 확인하세요. 납품실적의 공개 가능 여부도 확인합니다.

페이지별 title/description/OG 기본 메타는 들어 있습니다. 도메인 확정 후 canonical, og:url, og:image의 절대 URL을 추가합니다. 기존 대표 스킨의 SEO 설정과 중복되지 않게 확인합니다.

1440/1024/768/390px에서 상품 클릭→상세→상담/구매, 게시글 검색→상세→목록, 로그인, 실제 문의 저장과 비공개 권한을 검수한 다음 대표 디자인 적용을 결정합니다. 로컬 검수는 카페24 서버 기능 검수를 대체하지 않습니다.
